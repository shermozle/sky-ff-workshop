Deployments and keys.

Use the flag key to name a decision, the deployment key to connect its SDK, and the Analytics API key to send workshop data.

What is a deployment?

In this workshop, sky-workshop-web is the Amplitude deployment: the named group of flags available to the browser integration. It belongs to Feature Flag workshop. Attach your flag to this deployment so the app can request its decision.

One project can have several deployments, such as web, TV clients and a recommendation service. One flag can be attached to several deployments. A deployment does not host code or deploy a release. All participants share the workshop web deployment and use their own flag keys.

Example: the browser initialises its SDK with the shared client-… deployment key, then asks for alex-recommendations. The first connects it to the available flags; the second identifies Alex’s decision.

A naming trap in SDK examples

Experiment.initialize('CLIENT_DEPLOYMENT_KEY', { serverZone: 'us' });

The SDK may call its parameter apiKey, but Experiment initialisation expects a deployment key. The Analytics API key has a separate job: sending data into Analytics.

Names and IDs are different again

Participants select Feature Flag workshop by name. The technical project ID is 896821; the Sky NZ organisation ID is 74301. A deployment has a display name, a management ID and a generated deployment key. A flag has a display name, a management ID and its runtime flag key. Use the management IDs where API URLs request them; use the flag key in the app’s flag field.

Why a flag might not appear

Check the project, exact flag key, remote evaluation mode, activation and allocation, and association with sky-workshop-web. A matching name alone does not connect a flag to the app.
