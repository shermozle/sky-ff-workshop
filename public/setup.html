1. Confirm the project

2. Create the web deployment

Create a client-side deployment named sky-workshop-web. All participant and presenter remote flags must be associated with this deployment. Use the generated public client deployment key. Never put a server deployment key, project secret key or management key in these files.

3. Add browser configuration

The supplied Analytics API key and client deployment key are now set in public/config.js. Both must belong to the same project. The app can also accept public browser keys at runtime, saved in local storage. Once defaults are deployed, Incognito can connect without re-entering them. The URL includes scenario inputs only.

analyticsApiKey: 'APPROVED_PROJECT_ANALYTICS_KEY',
deploymentKey: 'APPROVED_CLIENT_DEPLOYMENT_KEY'

Practice mode makes no Amplitude requests. In live mode the app fetches decisions and Amplitude may record assignment events. Sending additional exposure and preview events is an explicit opt-in in connection settings.

4. Seed the fictional users

The presenter utility needs Node 20+ on the presenter’s machine only. Hosting remains entirely static. From the repository root:

node scripts/seed-users.cjs                  # dry run; no network

# After approval, provide environment variables securely:
# SKY_AMPLITUDE_API_KEY = the project's Analytics API key
# SKY_AMPLITUDE_PROJECT_ID = 74301
node scripts/seed-users.cjs --send

The initial run was accepted: five fictional profiles and 60 events. The script sends to the US HTTP V2 endpoint; avoid rerunning unless you intend to refresh the fixtures. It checks the accepted event count. Before sending, independently confirm that the key belongs to project 74301: the ingestion endpoint identifies the project from the key, not the numeric ID guard. Do this well before the session, then inspect every profile and test identity-only targeting. Accepted events do not establish enrichment readiness. Watch-event insert IDs are stable across reruns; profile seed events are reissued intentionally.
