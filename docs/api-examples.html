Flags through APIs.

These terminal examples are reference material. They are not executed by the static app.

Use a separately authorised management API key to change flags. The browser Analytics API key and client deployment key do not grant management access. Replace every placeholder and confirm the target project before running a write.

List flags in project 74301

curl --fail-with-body --get \
  'https://experiment.amplitude.com/api/1/flags' \
  --header "Authorization: Bearer $SKY_MANAGEMENT_API_KEY" \
  --data-urlencode 'projectId=74301'

Create a remote flag

Save this body as create-flag.json. Replace the participant prefix and deployment ID. This creates configuration; inspect and explicitly activate it after checking the audience.

{
  "projectId": "74301",
  "key": "yourname-recommendations",
  "name": "Your name recommendation rail",
  "evaluationMode": "remote",
  "variants": [{"key": "on", "name": "New rail"}],
  "rolloutWeights": {"on": 1},
  "deployments": ["YOUR_WEB_DEPLOYMENT_ID"]
}
curl --fail-with-body --request POST \
  'https://experiment.amplitude.com/api/1/flags' \
  --header "Authorization: Bearer $SKY_MANAGEMENT_API_KEY" \
  --header 'Content-Type: application/json' \
  --data-binary @create-flag.json

Roll back a flag

Use the management flag ID from the create response or Amplitude URL, not the runtime key. The app must fetch again to observe the change.

curl --fail-with-body --request PATCH \
  "https://experiment.amplitude.com/api/1/flags/$SKY_FLAG_ID" \
  --header "Authorization: Bearer $SKY_MANAGEMENT_API_KEY" \
  --header 'Content-Type: application/json' \
  --data '{"enabled":false}'

Creation, deployment association and disabling are documented by the management API flag endpoints. These writes have not been run against the Sky project.

Runtime evaluation from a server or terminal

This REST example needs a server deployment key for a deployment associated with the flag. It is separate from the browser deployment used by the app. Keep this credential outside the site.

curl --fail-with-body --get \
  'https://api.lab.amplitude.com/v1/vardata' \
  --header "Authorization: Api-Key $SKY_SERVER_DEPLOYMENT_KEY" \
  --data-urlencode 'user_id=sky-workshop-aroha' \
  --data-urlencode 'flag_keys=yourname-recommendations'

The evaluation API returns an assignment; it does not change the flag configuration.

What the browser SDK does

// Public CLIENT deployment key. Runtime request, not management.
const client = Experiment.initialize('CLIENT_DEPLOYMENT_KEY', {
  serverZone: 'us'
});
await client.fetch({
  user_id: 'sky-workshop-aroha',
  device_id: 'sky-workshop-aroha-web'
});
const variant = client.variant('yourname-recommendations');
const useNewRail = variant.value === 'on';

This identity-only request lets remote evaluation use already stored profile data. The app also offers explicit synthetic properties for the earlier exercises. See the SDK documentation for lifecycle and cache behavior. The app adds a timeout, transport error observation and an intentional default path.
