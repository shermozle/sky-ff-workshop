What is demonstrated

Practice mode simulates rules and a deterministic rollout in the browser. Its hash is not Amplitude’s bucketing algorithm. Live mode uses the unmodified Amplitude Experiment JavaScript SDK 1.15.5, pinned to the script-tag installation version shown in the documentation. The SDK is vendored locally with its MIT license so practice does not require a CDN.

What still needs live verification

The supplied public keys are configured. Real browser requests returned HTTP 200 with the expected high-engagement targeting: Aroha, Ben and Dev on; Casey and Ellis off. All five viewers passed in explicit and identity-only modes, with no targeting property values supplied in identity-only requests. The US ingestion endpoint accepted 60 events for five fictional profiles. Historical-profile targeting has been verified for the seeded viewers; live rollback remains unverified; management writes have not been exercised. Tests intercept the real SDK’s HTTP boundary and drive its real response handling. They validate integration contracts and UI behavior; they cannot establish the project’s permissions, targeting configuration or network readiness.

Latency interpretation

The inspector times the browser SDK fetch and local variant reads. It does not infer CDN cache hits and does not benchmark server local evaluation. Use Sky’s backend runtime, region, concurrency and p95/p99 measurements when deciding production architecture.

Prototype scope

All viewers, viewing activity, programme names and artwork are fictional. Subscription packages inform targeting examples; flag decisions do not replace content authorisation. The browser can select synthetic identities freely. This is not an authentication system. Live remote requests may create assignment records; optional app exposure and preview events are off until enabled.
