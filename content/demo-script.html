PRESENTER / APP DEMONSTRATION

Walk through Sky Lab.

Use this spoken script after the introductory slides have explained feature flags, what they control and evaluation. Actions appear alongside the words. Use it as a reference across the session; the full run of show holds the 90-minute timing.

Before starting: use presenter-recommendations on sky-workshop-web. The flag should target engagement_level = high at 100% to on, with everyone else off. Keep Amplitude open in another tab. Rollback is a live action you perform in Amplitude; the app fetches the updated decision afterward.

1 / Explain the experience

“This is a fictional Sky streaming interface. We’ve already deployed two ways to choose the recommendation rail: the default experience and a new personalised rail. The flag decides which path the app uses.”

“The recommendation titles are demo fixtures. Amplitude controls whether the new rail appears.”

2 / Orient the room

“On the right, we choose a viewer and the flag key. Each viewer has different subscriptions and engagement data. We’re using a real flag in our dedicated workshop project.”

“We’re in Live mode, so Evaluate flags sends a request to Amplitude’s US evaluation service.”

Do: confirm Live mode, select Aroha, enter presenter-recommendations, choose “Send identity + profile properties” and leave the optional promo key empty.

3 / Show Aroha’s result

“Aroha is a high-engagement viewer. Our rule enables the new rail for high-engagement users.”

Do: click Evaluate flags.

“The response is on, and the app displays ‘Picked for Aroha’. The inspector shows the identity, result and fetch timing.”

4 / Compare Casey

Do: select Casey, then click Evaluate flags.

“Casey has low engagement. With the same flag and application code, Casey receives off and sees ‘Popular this week’.”

“The change is in the targeting decision. We haven’t deployed another version of the app.”

5 / Demonstrate Amplitude’s stored user data

Do: select “Send identity only · use Amplitude profile”, choose Aroha and evaluate. Expand Request inputs.

“This time we haven’t supplied engagement or subscription values. The SDK includes identity and technical context, but the user-properties object is empty.”

“Amplitude uses the profile we seeded earlier to evaluate the rule. Aroha still receives on.”

Do: switch to Casey and evaluate again.

“Casey still receives off. That’s the connection between data Amplitude knows about a viewer and a feature-delivery decision.”

Checkpoint: Aroha is on and Casey is off, without targeting property values in either request. The Selected profile fixture panel shows local expected data; open the actual user profile in Amplitude to inspect the stored properties.

6 / Explain latency and caching

“The fetch timing includes the network request and SDK processing. It isn’t a production latency benchmark.”

Do: click Read cached decision · no fetch.

“This reads the result we already fetched. It makes no network request. It also doesn’t re-evaluate the targeting rules.”

“Local evaluation is a different operation: an SDK runs the rules itself against locally available user data and downloaded flag configuration.”

7 / Show rollback

Do in Amplitude: disable the presenter flag and save. Return to the app, select Aroha and click Evaluate flags. Confirm the default rail appears before continuing.

“Aroha now gets the default experience. We’ve withdrawn the new rail without deploying code.”

“In this app, we explicitly fetch after changing the rule. In production, the refresh strategy and fallback behavior are part of the architecture we need to design.”

Reset: reactivate the flag in Amplitude afterward, retaining the high-engagement targeting rule. Evaluate Aroha again to confirm the new rail returns.

8 / Connect it to Sky’s backends

“Today this browser requests the decision directly. For Sky’s recommendation or promo services, the decision could sit inside the backend.”

“The questions are: where should evaluation happen, which user data is available there, what latency budget do we have, and what should we serve if evaluation is unavailable?”

“Now you’ll create your own flag and control this same app.”
